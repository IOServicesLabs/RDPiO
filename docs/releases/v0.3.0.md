## rdpio 0.3.0

rdpio on Android: the Hyper stream and Windows 365 on a tablet, with touch,
trackpad, mouse and keyboard at once, made for the Snapdragon in the OnePlus
Pad 2. And a stream that holds up on a bad connection: over a relayed
Tailscale link carrying about 1 Mbps, where 0.2.5 queued seconds of video,
pictures now arrive in about 80 ms.

### rdpio for Android (new)

- **The Hyper stream on a tablet.** Sign in to a Hyper host by address and
  password; the stream is decoded by the tablet's hardware decoder (the
  Qualcomm low-latency decoder where there is one) straight to the screen.
- **Touch, trackpad, mouse and keyboard together.** Fingers on the screen
  are Windows touch (a new `Touch` input event; hosts that predate it get
  none), the keyboard cover's trackpad and a mouse move the pointer, Ctrl+Shift+M
  locks the mouse for games. Keyboards type in the PC's layout or the
  tablet's (input methods work); Ctrl+Alt+End is Ctrl+Alt+Del.
- **Esc is Esc.** A keyboard's Esc goes to the PC, also from keyboards (or
  remapping tools) that send it as Android's Back key. **Shift+Esc**, the
  back gesture or the round button opens the menu.
- **Game and office modes.** Game mode: 120 Hz, the high-performance cores,
  exclusive low-latency audio, and Snapdragon Game Super Resolution
  upscaling a 75% or 50% stream to the full screen. Office mode: native or
  scaled text, the panel at 60 Hz except while the pointer moves, and less
  work all round. **Auto resolution** picks the stream size the link carries.
- **Windows 365 on the tablet.** Sign in with the work account, or import a
  Cloud PC from the Windows App's `.rdp` file; the session runs on the same
  RDP stack as the desktop client (graphics, sound, microphone, camera, the
  display scale set from the tablet's density, Menu → Text size). Switch
  between sessions with Ctrl+Shift+Tab; they stay connected in the
  background.
- **The tablet's camera and microphone** on the PC (the host's rdpio Camera).
- Guide: [docs/android.md](https://github.com/IOServicesLabs/RDPiO/blob/main/docs/android.md).

### Hyper on a slow or relayed connection

Measured between the tablet and a Hyper host over Tailscale's relay (DERP
over TCP, ~1 Mbps, nothing dropped, everything queued):

- **The rate follows a queue that stands.** 0.2.5 kept aiming at 13-20 Mbps
  while about 1 Mbps got through. Now a queue every packet waits in is cut
  below what the link delivers, and video is skipped (before it's encoded,
  so nothing breaks) until it drains: round trip 75-80 ms, nothing lost.
  Simulated cold start on 1 Mbps: 20 s of latency → 0.1 s.
- **One keyframe at a time.** Repeated requests for a picture while one is
  on its way are folded into it (a cold start sent 29, now 1), keyframes are
  sized for the link (1 Mbps: 32 → 10 KB), and the client no longer drops a
  late burst and asks for another one.
- **Warm start.** The host remembers what each client's path carried and
  starts the next stream there: the first picture over the relay in 0.4 s
  instead of 2.7 s.
- **No creeping up on a slow path, no ratcheting down on its jitter.** An
  idle screen no longer climbs to 11 Mbps and floods the next scroll; a
  relay's ordinary jitter no longer holds the stream at its 0.5 Mbps floor.
- **Fewer, sharper frames when bits are short**: 60 → 30 → 20 fps, and in
  office mode on to 15 and 10, so text over 1 Mbps gets twice the bits a
  frame. Input still sends the next picture at once. Back up as the link
  allows.
- **Audio over a bad link.** Microphone forward error correction (10% loss:
  22 → 33 dB), game sound at 48-64 kbps when the link is short, and a
  backlog caught up with crossfaded splices (45 ms behind: 10 s → 0.5 s).
- **Input can't flood the link**: repeats capped to the newest 16 events,
  resent at the round trip.
- **Faster reconnects.** A connection silent for 3 s reconnects on its
  sign-in cookie, and the host keeps the virtual monitor for 15 s (drop to
  new stream: 15-28 s → a few seconds). After a restart the host waits for the
  console to settle instead of streaming its own monitor.
- **The path is shown**: the stats say `path: relay ord` (or direct, or LAN),
  and the host log warns when Tailscale relays.
- **A direct LAN path.** The host offers its LAN addresses; a client on the
  same network signs in there instead of through the VPN.

### Hyper speed and efficiency

- **Receiving costs less**: frame buffers reused (tablet 38 → 7 µs a
  frame), shards written straight into the frame, a ring instead of a tree
  for frames in flight, loss repair that solves only for what's lost (2.7x)
  with NEON on ARM (3.3x), fewer wakeups (an office receive nap, a 50 ms
  decoder wait, asynchronous MediaCodec: app CPU 45 → 36%).
- **Sending costs less**: the host packetizes and adds parity without
  allocating per packet, and sends 2% parity instead of 5% on a clean path.
- **AV1 with long-term references** on RTX hosts (NVENC API 13), opt-in for
  now (see docs/hyper.md).
- **Opus decoded on the receive thread** (audio wakeups 61 → 1 a second),
  microphone at the mobile complexity (26% less CPU on a small core).

### RDP and Windows 365

- **Faster graphics decode**: ZGFX 1.4-3.4x, ClearCodec 1.0-5.3x, both
  byte-identical to before.
- **The RDP stack builds without Windows**: RDSTLS and CredSSP have portable
  implementations (used on Android and Linux).
- **Display scale** is sent at connect and with each resize.

### Host

- Host behaviours can be switched off one by one for testing in
  `%PUBLIC%\rdpio-hyper-switches.txt` (`name=0`, read live), and the host's
  perf log says why the bitrate came down (`cuts=`). See docs/hyper.md.

### Downloads

- `rdpio-android.apk`: the Android app (Android 11 or later, arm64). Allow
  installs from this source when Android asks.
- `rdpio-windows-x86_64.zip`: rdpio.exe, its signed manifest and the README.
- `rdpio.exe` and `rdpio.exe.update`: what updates download.
- `rdpio-linux-x86_64.tar.gz`: the Linux build (headless, see PORTING.md).
- `*.sha256`: checksums of the archives.

A host and the clients that connect to it should run the same version.
